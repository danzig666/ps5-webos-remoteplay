# Software bug check — 2026-11-02

Reviewed the Rust application, extracted protocol control paths, C SDL/NDL bridge, controller output selection, private configuration, build/packaging scripts and existing test coverage. Baseline: `fc2e551b204937df7968ecc9671016426e3a2c68`. This is a software review and host/build verification, not proof of hardware functionality or absence of all bugs.

## Findings fixed

| Finding | Impact | Fix and regression evidence |
| --- | --- | --- |
| Initial IDR consumed before audio header; decoder could open on a dependent frame | Missing/corrupt startup video | Preserve queued video until audio is ready; require a keyframe when opening/reopening the decoder. Two headless media tests reproduce failures against the previous UI. |
| Duplicate audio packet flushed a full jitter buffer | Avoidable audio loss during transport redundancy | Ignore duplicates before overflow handling; test fills 24 slots and repeats a sequence number. |
| Release queued behind pending controller presses | Old presses could be delivered after opening the menu or disconnecting | Clear pending states before enqueueing neutral input. Queue regression covers a pending press. F1 menu resume also submits the current snapshot immediately. |
| Re-enabling USB effects did not resend cached trigger/LED state | Effects remained reset until the next console update | Mark output state dirty after resets/toggles and controller connection changes; capture FFI feedback in the regression test. |
| Disconnect retained raw rumble state | Changing strength could revive an old rumble command | Clear both raw and scaled rumble and its source state; regression reproduces the previous behavior. |
| USB audio haptics checked USB bus but not active controller type | With another active USB pad, an attached DualSense audio device could receive effects | Require the active pad to be a USB DualSense. Host C selection test covers Xbox, USB DualSense, Bluetooth DualSense and no controller. |
| Unbounded registration/session-init response buffering | Oversized control replies could exhaust TV memory | Limit each HTTP response to 64 KiB; test covers normal, exact-limit and endless readers. Recorded in the pinned protocol extraction patch. |
